# Idiomas (i18n)

La pantalla viene en español (`es`, el default) e inglés (`en`). Elegí con:

```bash
buddy.py --lang en     # o: --lang es
BUDDY_LANG=en buddy.py # la variable se lee cuando falta la opción
```

Solo cambia la pantalla. La terminal (teclas, `buddy.py check`, errores) y el registro siguen en español elijas lo que elijas.

## Dónde viven los textos

- **La página** (`ui/index.html`): la tabla `I18N`, una entrada por idioma, con todos los textos que muestra la pantalla. El daemon le dice a la página su idioma cuando la sirve (y en cada vista como `lang`). Una llave que falta en un idioma cae al texto en español.
- **El daemon** (`buddy_i18n.py`): el interruptor en sí (`LANGS`, `DEFAULT_LANG`, `parse_lang` para `--lang`, `normalize` para el código que no puede fallar) y una `TABLE` con los pocos textos que el daemon mete en la vista y la página muestra tal como llegan, hoy las razones de "Bluetooth no está listo". Esas razones las escribe en español `buddy_bluez.py` y se cambian al idioma elegido al armar la vista; una razón que no reconoce pasa sin tocar.

El código, los comentarios y el protocolo están en inglés. Todo lo que viene de afuera (el título de un hilo, un aviso, un pedido de permiso) se muestra tal como llega y nunca se traduce.

## Agregar un idioma

1. En `ui/index.html`, copiá la entrada `es` de la tabla `I18N` con un código nuevo (`fr`, `pt`, ...) y traducí cada valor. Mantené los textos cortos: el escenario es de 800x480 fijos y las filas de las listas miden 44 px de alto, así que mirá los más largos con las demos (`?demo=threads-long`, `?demo=cycle`; la lista completa es `DEMOS` en el archivo).
2. En `buddy_i18n.py`, sumá el código a `LANGS` y las mismas llaves a `TABLE`.
3. Corré las pruebas (`.venv/bin/python -m pytest tests -q`); las de la página recorren las demos.
4. Agregá `README.<código>.md` (y `docs/<código>/` si querés) y enlazalo desde `README.md`.

Pautas para cualquier idioma: tono amable, sin em dashes, y en español la pantalla usa voseo.
