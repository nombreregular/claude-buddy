# Languages (i18n)

The screen comes in Spanish (`es`, the default) and English (`en`). Choose with:

```bash
buddy.py --lang en     # or: --lang es
BUDDY_LANG=en buddy.py # the variable is read when the option is missing
```

Only the screen changes. The terminal (keys, `buddy.py check`, errors) and the log stay in Spanish whatever you choose.

## Where the texts live

- **The page** (`ui/index.html`): the `I18N` table, one entry per language, with every text the screen shows. The daemon tells the page its language when it serves it (and in every view as `lang`). A key missing in a language falls back to the Spanish text.
- **The daemon** (`buddy_i18n.py`): the switch itself (`LANGS`, `DEFAULT_LANG`, `parse_lang` for `--lang`, `normalize` for code that must never fail) and a `TABLE` with the few strings the daemon puts into the view and the page shows as they come, today the Bluetooth "not ready" reasons. Those reasons are written in Spanish by `buddy_bluez.py` and swapped for the chosen language when the view is built; a reason it does not recognise is passed on untouched.

Code, comments and the protocol are in English. Anything that comes from the outside (a thread title, a notice, a permission request) is shown as it arrives and is never translated.

## Add a language

1. In `ui/index.html`, copy the `es` entry of the `I18N` table under a new code (`fr`, `pt`, ...) and translate every value. Keep the texts short: the stage is a fixed 800x480 and list rows are 44 px high, so look at the longest ones with the demos (`?demo=threads-long`, `?demo=cycle`; the full list is `DEMOS` in the file).
2. In `buddy_i18n.py`, add the code to `LANGS` and the same keys to `TABLE`.
3. Run the tests (`.venv/bin/python -m pytest tests -q`); the page tests walk the demos.
4. Add `README.<code>.md` (and `docs/<code>/` if you like) and link it from `README.md`.

Guidelines for any language: friendly tone, no em dashes, and for Spanish the screen uses voseo.
